# ANOR — build log by phase

Each phase lists what was built and what is mocked / degraded when no provider is configured.

## Phase 0 — Foundation
**Built**
- Next.js 16 (App Router, Turbopack) + TypeScript, Tailwind CSS v4 design tokens (crimson/gold, surfaces, dark mode via `.dark` class + pre-paint theme script).
- Prisma 7 (driver adapter `@prisma/adapter-pg`, `prisma.config.ts`), full data model (~100 models) + migration adding `pg_trgm`/FTS indexes.
- next-intl with three locales: Uzbek Latin (`/`), Uzbek Cyrillic (`/oz`), Russian (`/ru`). Messages are authored per namespace in uz + ru; `uz-Cyrl` is generated by a Latin→Cyrillic transliterator that preserves ICU syntax (`npm run i18n`).
- `<AnorLogo />` (full / symbol / wordmark × color / white / dark), favicon (`app/icon.svg`), static brand SVGs, living style guide at `/design`.
- UZS formatting (`1 250 000 so‘m` / `сўм` / `сум`), Asia/Tashkent date helpers, `.env.example` with comments for every variable.

**Mocked** — nothing yet.

## Phase 1 — Auth, RBAC, audit
**Built**
- Users: unique login/ID code (4–20, `[A-Za-z0-9_]`, reserved names blocked), password ≥ 10 with strength meter, optional phone with SMS OTP verification, Google OAuth (PKCE) and Telegram Login Widget (HMAC verified).
- argon2id (OWASP params) for passwords, PIN and staff access codes; HMAC for OTP/recovery codes; constant-time comparisons; generic errors; dummy hash on unknown accounts (no timing enumeration).
- Lockout after 5 failures for 15 min; rate limits per IP and per account (Upstash REST or in-memory); login history with device/IP; "log out everywhere"; per-session revoke.
- Optional 6-digit PIN second factor asked on every new (untrusted) device; device trust stored per device cookie hash.
- 10 one-time recovery codes shown once (encrypted short-lived cookie, never stored in clear); password reset via phone OTP or recovery code (all sessions revoked).
- Cookie sessions: random token, SHA-256 in DB, httpOnly + secure + SameSite=Lax, rotated on login, PIN verification, password change and privilege change; staff sessions separate (12 h absolute, 2 h idle).
- CSRF: Origin / Sec-Fetch-Site check on every server action and mutating route handler (stricter than Next's built-in check).
- Staff: hidden `/staff/login` (login + password + admin access code + optional TOTP), failed staff logins alert the owner (email + Telegram, throttled).
- Invites: SUPER_ADMIN picks role + permission overrides → one-time code/link (48 h, single use, atomic claim, revocable); employee sets login, password and own access code.
- Promote existing user (one-time access code), change role, suspend/restore/remove (staff sessions revoked instantly), last SUPER_ADMIN protected, no privilege escalation (`staff.manage`, `roles.manage`, `system.demo_reset` are SUPER_ADMIN-only and cannot be granted via overrides).
- Custom roles with permission matrix; RBAC checked in every server action (`action({ permission })`) and page (`requireStaff`).
- Audit log (who, what, when, IP, UA, before/after with secrets redacted), filters, CSV/XLSX export (formula-injection safe).
- Seed: permissions, system roles, owner from env (refuses placeholders in production), demo staff of every role (random passwords; one-click demo login in DEMO_MODE).
- `instrumentation.ts`: refuses to boot production with placeholder secrets; error reporting to logs, `ErrorEvent` table and Sentry envelope API.

**Mocked / degraded**
- SMS: console driver logs codes; in DEMO_MODE the code is also shown in a toast. Eskiz driver is implemented but untested without credentials.
- Google / Telegram: without credentials, DEMO_MODE signs in deterministic test accounts.
- Email: console driver (Resend and SMTP/Mailpit implemented).

## Phase 2 — Catalog, search, product page, cart, wishlist
**Built**
- Seed: 51 categories (11 roots incl. crafts), 4 shops (official electronics store, fashion, artisan workshop, halal food), 9 brands, 54 products with uz/ru content, UZS prices, variants, per-warehouse stock (platform FCs for FBO, seller warehouses for FBS/DBS), 90-day price history, installment plans, 12 pickup points, coupons, promotions (multi-buy, bundle, buy-together), banners, deal of the day, a live flash sale and scheduled seasonal campaigns (Navro‘z, Mustaqillik, 11.11, Qora juma), seller + artisan stories.
- Home: hero carousel (swipe/autoplay/reduced-motion aware), perks, stories viewer, category grid, deal of the day with countdown, flash sale, popular, Plus strip, new arrivals, Made in Uzbekistan, personalized recommendations (view-history category affinity) and recently viewed.
- Catalog `/c/[slug]`: subcategory chips, URL-driven filters (price, brand facets with counts, rating, delivery today/tomorrow, in stock, halal, Made in UZ, used), 6 sorts, infinite scroll over `/api/v1/products`, mobile filter sheet, breadcrumbs + BreadcrumbList JSON-LD.
- Search: Postgres FTS + pg_trgm word-similarity per word (typo tolerant, Latin/Cyrillic/Russian), "did you mean", autocomplete API with products/categories/brands, search history (local) and trending queries (logged after response), voice search (Web Speech API), image search (Gemini vision or filename fallback).
- Product page: gallery with hover zoom, swipe, fullscreen lightbox and video; variant picker linked to photos; price/old price/discount; "lowest in 90 days" badge; price history chart (crosshair tooltip, keyboard, table view; palette validated in light/dark); Nasiya calculator (3/6/9/12 months); delivery ETAs by fulfillment model (Tashkent same-day cutoff 14:00); seller card; specs; size guide; wholesale tiers; share; compare; price-drop and back-in-stock alerts; pre-order; similar and "customers also bought" (order co-occurrence); recently viewed; Product JSON-LD.
- Cart: guest cart (httpOnly cookie) merged on login, optimistic quantity/select/remove, grouped by shop, unavailable items, promo codes with precise error reasons, promotions, wholesale pricing for business buyers, cashback preview, monthly installment, move to wishlist, group carts (share link; members add, owner checks out).
- Wishlist with optimistic hearts and shareable public link; compare up to 4 products (spec diff highlighting); brand, shop, deals, campaign landing (block-based) and Made in Uzbekistan pages.
- Pure, testable engines: `lib/pricing.ts` (coupons, promotions, allocation, bonus cap, cashback, commission, logistics fee), `lib/installment.ts`, `lib/delivery.ts`.

**Mocked / degraded**
- Product imagery is generated SVG art (`/media/demo/*.svg`); real uploads arrive with the seller cabinet.
- Image search without `GEMINI_API_KEY` uses filename keywords.
- Product videos point to a public CC0 sample clip.

## Phase 3 — Checkout, payments, orders, pickup points, wallet
**Built**
- Checkout: pickup point (map + list picker), courier with 2-hour slots, express (Tashkent + FBO only); saved addresses with Leaflet map pin; gift orders (hidden price, greeting, recipient); live re-quoting; bonus slider (≤ 30%), wallet balance, saved cards, Nasiya plan picker when a limit exists.
- One checkout → one `OrderGroup` split into per-shop orders; prices recomputed server-side; stock reserved atomically per warehouse (conditional decrements, buyer's region first); coupon usage limits enforced atomically; commission and logistics fee per line; cashback by tier/Plus.
- `PaymentProvider` interface with mock Click, Payme, Uzcard, Humo, Visa/MC (hosted test page with 3-DS style code `000000`, tokenized card saving, signed server callback endpoint), COD, wallet, installment (contract + repayment schedule created at checkout).
- Order state machine (pure + tested later) with role rules; shipments (FBO/FBS/DBS, 24 h FBS handover SLA), pickup point storage (5 days, reminders, auto-return), 4-digit code / QR handover, cancellation with stock release and proportional refunds (bonus → bonus, wallet → wallet, rest → card), cashback paid on delivery, loyalty tier recompute, referral rewards with fraud limits, achievements.
- Fiscal receipts via a `TaxProvider` mock (VAT 12 % included), PDF receipt (pdf-lib + DejaVu, QR) and public verification page.
- Account: orders list with tabs, order detail with timeline, tracking, pickup code + QR, receipt, cancel, return request with photos; returns list; addresses; notifications (in-app + channel preferences).
- Anor Hamyon: top-up, transactions, saved cards, bonus history with expiry, service payments (mobile, internet, utilities, QR), wallet-to-wallet transfers, gift cards (buy + redeem).
- Courier app `/courier`: route list + map, take jobs, confirm by code, failed attempts, COD cash notice.
- Infrastructure: realtime bus (in-process + Postgres LISTEN/NOTIFY), notification service (in-app, email, SMS, Telegram, Web Push), job registry with inline / pg-boss drivers, `npm run worker`, `/api/cron/[job]` for Vercel Cron, upload API with type/size/magic-byte checks and virus-scan hook, local / Supabase storage.
- Jobs: unpaid checkout expiry, PVZ reminders/returns, FBS SLA penalties, bonus expiry, price-drop/back-in-stock alerts, scheduled price changes, webhook delivery with retries.

**Mocked / degraded**
- All card rails are mock gateways (no real money); refunds are simulated.
- Fiscal operator (OFD) is mocked; receipt QR points to our own verification page.
- Service payment providers (Ucell, Uztelecom, utilities…) are mock billers debiting the wallet.
- Map tiles default to public OpenStreetMap tiles (set `NEXT_PUBLIC_MAP_TILE_URL` for production).
- In DEMO_MODE buyers see a "Demo: next step" button to advance their own orders.

## Phase 4 — Reviews (buyer, seller, moderation)
**Built**
- Reviews only from delivered orders (one per product per order), "Verified purchase" badge, 1–5 stars (accessible radio-group picker), pros / cons / comment, up to 6 photos + 1 video (uploads restricted to our own storage URLs), anonymous option, edit window of 14 days, a few words required for ratings ≤ 3.
- Product page: rating breakdown bars that act as filters, "What buyers say" summary, buyer photo strip with lightbox, filters (rating, with photo/video, variant) and sorts (helpful, new, high, low) loaded through a server action, "load more", helpful / not-helpful votes (optimistic, server-authoritative counts), reports with reasons, seller replies, the viewer's own review pinned first (including while in moderation), on-demand translation uz ↔ ru (cached on the review), Uzbek Latin text transliterated in the Cyrillic UI.
- Q&A: questions from signed-in users; answers from the seller (badge) or from buyers who received the product; contacts masked; risky text held for moderation.
- Shop ratings (delivery speed, packaging, communication) per delivered order; shop rating = 70 % product reviews + 30 % shop ratings; seller response time tracked from replies.
- Rule-based moderation (`lib/review-moderation.ts`, unit-tested): profanity stems (uz Latin/Cyrillic, ru), phones / links / handles / emails, spam heuristics, duplicate text, 5★ from accounts younger than 7 days, bursts of fresh-account 5★ on one product (raises a `FAKE_REVIEW` fraud flag). Flagged content goes to the queue instead of publishing; 3 independent user reports pull a review back into moderation.
- "What buyers say": recurring whole clauses from pros/cons plus non-overlapping two-word topics, computed per review language; Gemini summary (uz + ru) when `GEMINI_API_KEY` is set. Rebuilt by the `reviews.summary` job after every change and nightly.
- Photo/video review bonus (5 000 / 10 000 bonus) after approval, capped at 10 per 30 days; review mission progress.
- Account: `/account/reviews` (awaiting review, shops to rate, written reviews with status / reject reason / bonus / seller reply), new and edit forms; shop rating on the delivered order page.
- Seller cabinet shell `/seller` (sidebar, badges): reviews inbox (unanswered / negative / removal requests / all, reply with automatic contact masking, removal requests with reasons) and questions inbox; KPIs (average rating, reply rate, response time).
- Admin `/admin/moderation/reviews`: flagged (sorted by risk score), reported, seller removal requests, pending Q&A, pending shop ratings, decision history; bulk select with approve / reject (reason required) / hide / strip contacts / ban reviewer / dismiss reports / grant or deny removal; every decision logged in the review's moderation history and the audit log; nav badge counts. Analytics page: weekly average rating and review volume (two single-axis charts with table views), most-reported products, seller reply rate and response time.
- Seed: 24 reviewer accounts, ~240 reviews with delivered orders, votes, photos, seller replies, shop ratings and Q&A, plus moderation cases (phone number, link, insult, fresh-account 5★ burst, user reports, a seller removal request, a pending question). The demo buyer has delivered orders waiting for a review and one editable review.

**Mocked / degraded**
- Review translation and the AI moderation / summary layer need `GEMINI_API_KEY`; without it the "Translate" button is hidden and summaries are rule-based.
- Seller cabinet sections other than reviews and questions are placeholders until Phase 6.
- Review videos are stored as uploaded (no transcoding / duration check beyond the 50 MB upload limit).

## Phase 5 — Chat, support inbox, broadcasts
**Built**
- Realtime: `/api/realtime` Server-Sent Events stream per user (staff variant with the support desk channel), heartbeat + presence (`lastSeenAt`), Postgres LISTEN/NOTIFY fan-out across instances, and a polling fallback (`/api/realtime/poll`, 5-minute event history) that the client switches to automatically after repeated SSE failures or when `REALTIME_DRIVER=poll`. Live chat badge in the header and seller sidebar.
- Telegram-style messenger (`/chat`, `/chat/[id]`, seller `/seller/chats`): chat list with avatars, last message, unread badges, pinned/muted chats, online dots and search (participants + message text); bubbles with day separators, timestamps, reply-to quotes, edit (48 h) and delete own messages, emoji picker, typing indicator, online / last seen, sent → delivered → read ticks, history paging, "new messages" jump button, mobile single-pane layout.
- Attachments: images (grid + lightbox), files (type/size/magic-byte checks and scan hook via the upload API, chat folder only), voice notes recorded in the browser with a live waveform and a seekable player; product and order cards posted when a chat is opened from a product or order.
- Conversation types: buyer ↔ support (always-available "ANOR Yordam" chat, a new ticket per issue), buyer ↔ seller (one thread per buyer and shop), seller ↔ support.
- Privacy and safety (`lib/chat.ts`, unit-tested): phones, links, @handles and emails masked in buyer ↔ seller chats, profanity starred out, repeated-message spam flagged, report message, block user, per-chat mute, chat ban by moderators. Offline recipients get one push/Telegram notification per unread streak.
- First-line bot: suggests matching help-center articles before an agent replies (rule-based keywords).
- Support desk `/admin/support`: queues (open / mine / unassigned / waiting / resolved / all), full-text search, priority filter, 15-minute first-reply SLA timers, assign / take / transfer, status and priority, tags, internal notes invisible to the customer, canned replies with `/shortcut` (`/admin/support/canned`), customer card (orders, spend, returns, tier, Plus, shops, fraud flags, previous tickets). SUPER_ADMIN can answer any support conversation. Jobs: SLA escalation every 5 minutes, auto-resolve after 3 days waiting for the customer.
- Moderation `/admin/chats`: reports, flagged and recent buyer ↔ seller chats as metadata only; reading a chat requires a written reason, is recorded in the audit log and lasts 30 minutes; moderators can delete messages, resolve reports and ban users from chat.
- Broadcasts `/admin/broadcasts`: segments (all, buyers, sellers, Plus) with live recipient counts, in-app / push / email / Telegram channels, batched delivery job, history.
- Help center `/help` (search, sections, articles in uz/ru with Cyrillic transliteration) and an admin article editor.
- Seed: 11 help articles, canned replies, six tickets in every state (incl. a seller ticket and an SLA breach), buyer ↔ seller chats with a product card, a masked contact and a reported message, a past broadcast.

**Mocked / degraded**
- The first-line bot is keyword-based; an AI chatbot arrives with the assistant in Phase 8.
- Telegram bridge (bot messages into the same inbox) is Phase 8; push and Telegram notifications need VAPID keys / a bot token.
- Virus scanning uses the existing hook (EICAR signature check) — plug in ClamAV or a cloud scanner for production.
- Presence is approximate (SSE heartbeat every 25 s, considered online for 75 s).

## Phase 6 — Seller cabinet, fulfillment, analytics, ads
**Built**
- Onboarding wizard `/seller/onboarding`: legal form (LLC / individual entrepreneur / self-employed) with STIR or PINFL validation, shop profile and logo, seller warehouse, encrypted bank account with MFO check, documents per legal form, submission to moderation (KYC level 1), status and rejection reason; DEMO_MODE can approve the shop instantly. Several shops per account with a shop switcher.
- Cabinet layout with grouped navigation, live badges, banners for unapproved and restricted shops. Dashboard: 7-day KPIs against the previous week, a 30-day revenue chart, top products, an action list (new orders, late or near-deadline FBS handovers, returns, disputes, stock, unanswered reviews and questions, drafts, open platform campaigns) and the next payout estimate.
- Products: list with tabs, search, sort and bulk actions (price ±%, stock, status, delete); editor with photos (reorder, cover), variants with SKU / barcode / price / old price / private cost price / stock, scheduled price changes, specs, FBO/FBS/DBS, weight, wholesale tiers and a live unit-economics panel. Category suggestion (AI when `GEMINI_API_KEY` is set, otherwise similar products and name matching). Rule-based pre-moderation of risky listings. CSV import with preview and per-row errors, CSV export and template. A/B tests (Pro) of titles or cover photos: stable 50/50 split per visitor on the first listing page, click attribution on the product page (the arm must match the visitor's assignment), leader shown live, winner applied in one click.
- Orders: tabs, search, bulk confirm / pack / hand over, live FBS SLA timers, seller cancellation with reasons (counts against the rating), DBS hand-over with the buyer's code, order detail with money breakdown; the delivery address is shown only for DBS. Printable 100×150 mm packing slips with QR codes.
- Returns and disputes: approve, or contest with photo/video evidence; full timeline; returns not answered in 72 hours are approved automatically.
- Stock: per-warehouse quantities (own warehouse editable, ANOR warehouses read-only with reservations), low-stock filter, daily low-stock alerts and the `stock.low` webhook; FBO supplies created → accepted → received → in stock; barcode scanner PWA page (camera via BarcodeDetector, manual entry fallback) with receive (+1) and stock-count modes.
- Analytics: revenue, orders, average order value, units, views, conversion, cancellation and return rates for 7/30/90 days with deltas, daily charts (two single-axis charts with table views), top products, unit economics per SKU, a commission and logistics calculator, Excel export.
- Finance: current week accrual, weekly payouts (generated Mondays, paid Wednesdays) with reconciliation lines and Excel export per payout, penalties. Negative weeks are netted against later weeks instead of being "paid"; payouts are held for 48 hours after the payout account changes.
- Ads: search (keywords) and category placements, CPC or CPM bids with minimums, daily and total budgets with pacing, "Reklama"-labelled sponsored cards in search and category listings, ranking by bid × quality (CTR, shop rating), HMAC-signed click links with per-visitor click de-duplication, 7-day last-click order attribution, stats (impressions, clicks, CTR, CPC, spend, orders, revenue, ROAS). Restricted shops are not served.
- Rating `/seller/rating`: 90-day fulfillment score from SLA (35 %), reviews (35 %), seller cancellations (20 %) and returns (10 %); components with tips, warnings and penalties. Below 80 → warning; below 65 → ads stop, products rank lower and platform campaigns are closed; recovery lifts the restriction automatically. Pro shops below 80 drop back to Basic.
- Academy and tiers `/seller/academy`: four courses with lessons and quizzes (answers stay on the server, 80 % to pass, certificates stored). Pro requires score ≥ 85, 30 days on the platform, 20 orders in 90 days, KYC level 2, the two required certificates and no restriction. Pro gives a commission 2 percentage points lower, A/B tests and competitor price monitoring.
- Competitor prices (Pro) `/seller/competitors`: other shops' offers matched by shared barcode or by title similarity within the same category and brand; position (cheapest / competitive / more expensive / no competition), median and rank, "match the lowest price" in one click. Barcodes are now unique per shop rather than globally, since several shops sell the same EAN.
- Promotions: join platform campaigns with an "honest discount" check against the lowest price of the last 30 days (no raising the price right before a sale), optional stock limit, leave until the campaign starts; own promotions (multi-buy, bundle, buy together) with schedules.
- Seller API `/seller/api`: API keys (shown once, SHA-256 stored, scopes, revoke, last used, up to 5), versioned endpoints `/api/seller/v1` for products, single SKU, stock (single and bulk up to 500), price, orders and order status, with per-key rate limits and stable JSON errors. Webhooks for `order.created`, `order.cancelled`, `order.delivered`, `return.created` and `stock.low`: HMAC-SHA256 signature over timestamp and body, secret shown once and rotatable, test ping, delivery log with payloads and redelivery, retries with backoff, auto-disable after repeated failures. Outbound calls go only to public HTTPS hosts: the resolved IP is checked when the connection opens (blocks private, loopback, link-local and metadata addresses, including DNS rebinding), and redirects are not followed. Docs with examples and signature verification.
- Settings: shop profile, logo and banner (slug fixed after approval), payout account change with password or PIN re-confirmation plus SMS / Telegram / email alert, documents and KYC level, seller warehouses.
- Jobs: payouts generate and settle, return auto-approval, low-stock digest.
- Seed: cost prices and logistics fees on existing data; active orders with SLA timers (one about to expire, one late) for two shops; six weeks of payouts; three ad campaigns with three weeks of stats; FBO supplies in three stages; a pending return and a disputed one; a penalty and a resolved warning; certificates; promotions and campaign participation; a running A/B test; a competitor shop ("Gadjet Markaz") with shared barcodes. New one-click demo login: "Pro sotuvchi" (TechHub, Pro tier).

**Mocked / degraded**
- Payouts are marked paid with a generated reference; there is no bank integration.
- Shop moderation and dispute decisions belong to the admin panel (Phase 7). Until then, DEMO_MODE offers "approve" and "next stage" buttons for shops and FBO supplies.
- The barcode camera uses the browser's BarcodeDetector (Chromium/Android). Other browsers fall back to typing or a USB/Bluetooth scanner.
- A/B tests run on the first, server-rendered page of listings. Later pages are publicly cached and show the original. Title tests apply to the Uzbek UI only.
- AI category suggestion needs `GEMINI_API_KEY`.
- Webhook deliveries need outbound internet; in this sandbox they fail with a DNS error, which the delivery log shows.
